Prototype · trueseal-roadmap#12 · throwaway

One SDK API across Swift, Kotlin and TypeScript

A sketch, not compiled code. Every area of the public API appears side by side, with a note on how it differs from today's SDKs. Each platform stays idiomatic, but the names, cases and behaviour match. It builds on the delivery, pairing, size, versioning and membership decisions (ADR-0022 to ADR-0027).

Choices to react to

  • Entry type is TrueSealIt replaces TruesealSyncClient, and the brand is written TrueSeal everywhere. Package names belong to the distribution decision.
  • One relay address stringIt holds the key, the host and both ports, and the relay CLI prints it. This fixes the Swift port bug by construction.
  • Handlers, not streamsonMessage, onEvent and onDeliveryIssue are the same in every SDK. Only state uses platform-native observation.
  • No rejectAn unaccepted join request just expires when the window closes.
  • The object outlives the groupAfter removal, leave or destroy, the same TrueSeal object is back to notJoined with a fresh identity and can pair again.
  • members excludes youme is separate, as today.

Setup and relay address

Today: Swift takes a URL and silently drops its port, while Kotlin and TS take a bare host. The key is raw bytes, and the core hardcodes ports 7700 and 7701.

One RelayAddress everywhere, parsed from one pasteable string that trueseal-relay address would print: trueseal://<key hex>@host[:receivePort][?push=port]. There's also a typed form. open() is async in all three SDKs.

Lifecycle

Today: Swift has no teardown, TS dispose() only removes listeners, and Kotlin close() tears down the session.

close() in all three. The outbox and Session State persist; the next open() resumes.

Receiving messages

Today: streams and EventEmitters fire and forget, and the relay ack goes out before the app has seen the message.

One awaited handler (ADR-0026). Registering it starts receiving, and returning from it acks the message. message.from is a Member, so it matches members. Today TS's sender id doesn't.

Sending

Today: publish (Swift and Kotlin; Kotlin's is synchronous) versus send (TS). None of them return anything.

send everywhere. It returns the MessageId, so a later sendFailed can be matched to it. The publish(text:) helpers are dropped.

Status, identity and connection

Today: localNodeId and localDeviceName, a boolean connection state, and no join state.

New join status (ADR-0023, ADR-0027). me replaces the two local fields. The connection can report relayVersionUnsupported (ADR-0022). Each SDK exposes state the way its UI framework expects: Swift @Observable, Kotlin StateFlow, TS getters plus events.

Pairing: admitting a device

Today: generatePairingToken or pairingToken. acceptPairingRequest returns a Bool that Swift and Kotlin throw away.

startPairing() and accept(request). accept throws pairingClosed or groupFull instead of returning false. There is no reject, because the protocol sends no decline (ADR-0023).

Pairing: joining

Today: joinGroup(token), with no way to cancel and no pending state.

join(token) and cancelJoin(). The Pending Join is visible in status and survives restarts.

Members, remove and leave

Today: removeMember takes a member object in Swift and Kotlin but an id string in TS. There is no leave, and wiping after removal is left to the app.

remove(memberId) and leave() everywhere. On removal or leave the library wipes the device and gives it a fresh identity (ADR-0027). The same object stays usable.

Destroy Group

Today: destroyGroup() wipes the device and leaves the session unusable.

Provisional. The name stays. What happens afterwards depends on the Destroy Group decision (trueseal-roadmap#10). The sketch assumes it behaves like removal: back to notJoined with a fresh identity.

Events

Today: Swift has 4 AsyncStreams, Kotlin 4 Flows, and TS 7 string-named events.

One event type, handled with an exhaustive switch or when. Member changes arrive as the whole list, since ADR-0027 says to render the list and not trust individual joined and left events.

Delivery issues

Today: nothing. Failures are silent.

One optional stream with the same six cases in every SDK (ADR-0026). Each case carries a Message ID when one exists.

Errors

Today: Swift has a typed enum and Kotlin a sealed class (8 cases each), while TS has a single untyped error that holds only a message.

The same 12 cases in all three SDKs. In TS that is one error class with a code string union and typed extras.

Version and limits

Today: nothing is public. TS has a hidden native version().

Static info with the SDK version, the Transport and End-to-End Versions, and the two protocol limits.
